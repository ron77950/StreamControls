# Google OAuth setup

1. Enable YouTube Data API v3 in a Google Cloud project. Configure the external audience, support contact, developer contact, and `https://www.googleapis.com/auth/youtube` scope. While in Testing, add the Google Accounts used by testers. Testing grants can expire; public use requires Google's applicable OAuth verification.
2. Create an Android OAuth client for package `com.streamcontrols.app` and the SHA-1 of the actual debug signing certificate (`gradlew.bat :app:signingReport`). Enable the client's custom URI scheme in Advanced settings. In ignored `local.properties`, add `streamcontrol.debugClientId=YOUR_ANDROID_CLIENT_ID`; the previously used `streamcontrol.browserClientId` remains a debug-only fallback.
3. Install the debug build on Android 8 or later with an Auth Tab capable browser. Connect through Google, select the intended YouTube channel, verify its displayed name, and confirm. The Android client and OAuth project must permit the account being tested.
4. For a release, separately register the certificate actually used to sign the installed APK, including the Google Play App Signing certificate when applicable, and set `streamcontrol.releaseClientId=YOUR_RELEASE_ANDROID_CLIENT_ID` in `local.properties`. An unset release client ID cannot connect. Do not ship a debug-signed release or use a web client secret in the app.

StreamControl checks for an enabled Chrome installation with Auth Tab support first, even when another browser is the device default. If Chrome is unavailable or incompatible, it tries the preferred browser if that browser supports Auth Tab. If neither works, enable or update a supported browser; changing the system default is not required when compatible Chrome is installed.

Google's [older Console guidance](https://support.google.com/googleapi/answer/6158849) describes enabling Android custom URI schemes, but its [OAuth guide](https://developers.google.com/identity/protocols/oauth2/native-app) says custom schemes are no longer supported on Android. The opt-in browser flow returned the intended Brand Account in one debug test, but current release compatibility is not established. Custom schemes can permit app impersonation; PKCE prevents stolen authorization codes from being exchanged without the verifier but does not prove the initiating application's identity. Auth Tab support is required; no fallback redirect activity is registered. If the provider rejects the configuration, do not bypass the restriction with a desktop client, embedded WebView, or client secret.

A regular Custom Tabs fallback would require an exported redirect activity and separate handling of the callback and cancellation. State and PKCE would still be required, but a custom-scheme callback can be intercepted or disrupted by another app. Google documents that fallback for general Auth Tab integrations, while its Android OAuth guidance conflicts with custom-scheme support. This app does not implement that fallback without verifying a supported, safe redirect and testing its behavior with real accounts.

On connect, Google may show an account/channel selector and consent. The app requests offline access, uses a DPoP proof backed by an Android Keystore signing key, requires a refresh token, and verifies the resolved YouTube channel. Repeat the flow to add another channel. It stores a separate encrypted refresh token for each channel and checks that channel's ID when restoring and before operations. Existing connections made without DPoP must reconnect to obtain a bound token; they are not automatically revoked. If secure storage or token refresh fails, reconnect. Google may revoke grants for other channels or clients of the same project and account when access is revoked. DPoP and multi-channel selection, restoration, and revocation have not yet been verified with real accounts.

For a release, prepare the applicable homepage, privacy policy, OAuth verification, demo, YouTube policy compliance, and signing configuration. Review the [YouTube API setup](https://developers.google.com/youtube/v3/getting-started); API quota extensions and OAuth verification are separate processes. No client secret is needed in the Android app.

# Troubleshooting

A successful Google authorization does not prove the intended channel was selected. Check the displayed channel before confirming. YouTube Studio channel permissions and Brand Account ownership are distinct; [Google notes](https://support.google.com/youtube/answer/9481328) restrictions on invited channel-permission users' API access. Do not transfer ownership automatically. An empty active stream list is normal when no broadcasts are live; `liveStreamingNotEnabled` means YouTube reports the channel is not enabled for live streaming. Google API Explorer uses a different OAuth client and is only an independent comparison.
